# Constitución técnica del backend

## Objetivo

Exponer una API REST para autenticar administradores y consultar, registrar y actualizar motos del catálogo `catalogoMotos`.

## Stack y runtime

- TypeScript sobre Node.js.
- Hono como framework HTTP.
- PostgreSQL mediante `pg`.
- Despliegue como función Node.js en Vercel.
- `src/index.ts` exporta la instancia de Hono como `default`.

No se utiliza Edge Runtime porque `pg` y `bcrypt` requieren compatibilidad con Node.js.

## Arquitectura

```text
Routes -> Controllers -> Services -> Repositories -> PostgreSQL
```

- `routes`: endpoints, middleware y validación de entrada.
- `controllers`: HTTP, cookies y códigos de respuesta.
- `services`: autenticación y reglas de negocio.
- `repositories`: consultas parametrizadas.
- `database`: pool singleton para reutilización en funciones serverless.
- `schemas`: validación Zod.
- `middlewares`: autenticación, validación y errores.

## Autenticación y seguridad

El inicio de sesión busca el usuario y compara la contraseña con `bcrypt` usando el número de saltos definido en `BCRYPT_ROUNDS` (por defecto 8). El JWT se guarda en una cookie `HttpOnly`, `SameSite=Lax` durante desarrollo y `SameSite=None` con `Secure` en producción para permitir la comunicación entre los dominios de Vercel. El token expira según `JWT_EXPIRES_IN`.

Las contraseñas no se devuelven por la API. La contraseña de la base de datos debe estar almacenada como hash bcrypt; el registro de desarrollo existente con contraseña plana debe migrarse antes de usar el login.

## Endpoints

### `POST /api/auth/login`

Body: `{ "usuario": "sabino007", "contrasena": "..." }`.

Responde `200` con el usuario y establece la cookie. Credenciales inválidas responden `401`.

### `POST /api/auth/logout`

Elimina la cookie y responde `200`.

### `GET /api/motos`

Acepta los filtros opcionales `modelo`, `marca`, `categoria`, `cilindrada`, `precioMin`, `precioMax` y `stockDisponible`.

### `POST /api/motos`

Requiere JWT. Valida y registra `modelo`, `marca`, `categoria`, `cilindrada`, `precio`, `imagenLink`, `stock` y `descripcion`. Responde `201`.

### `PUT /api/motos/:identificador`

Requiere JWT y acepta actualización parcial. Responde `200` o `404` si no existe.

## Variables de entorno

La plantilla está en `.env.example`. El archivo `.env` nunca debe subirse al repositorio. Son obligatorias `DATABASE_URL` y un `JWT_SECRET` de al menos 32 caracteres.

## Ejecución y despliegue

```bash
npm install
npm run dev
npm run build
```

Para Vercel se configuran las variables de entorno del archivo `.env.example`; `vercel.json` dirige las solicitudes a `src/index.ts`. En desarrollo local puede utilizarse `vercel dev` (comando correcto; no `vc dev` si el CLI no define ese alias).

## Fases

1. Constitución, scripts y configuración.
2. Entrada compatible con Vercel y ruta de salud.
3. Pool singleton y repositorios PostgreSQL.
4. Schemas Zod y respuestas de validación.
5. Login, bcrypt, JWT, cookie y logout.
6. Registro y actualización protegidos de motos.
7. Listado y filtros parametrizados.
8. Manejo global de errores.
9. Pruebas de autenticación, CRUD, filtros y conexión.
10. Variables de producción, CORS, HTTPS y despliegue.

## Criterios de seguridad

- Nunca concatenar valores recibidos en consultas.
- Nunca almacenar ni responder contraseñas planas.
- Mantener `.env` fuera del repositorio.
- No exponer detalles internos en errores de producción.
- Mantener las operaciones de escritura protegidas por JWT.
